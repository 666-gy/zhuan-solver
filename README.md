# 砖了个砖 · 本地求解器

> 在线版（手机也能用）：https://666-gy.github.io/zhuan-solver/
>
> 离线版：下载本仓库，双击 `打开本地求解器.bat`。

从 `zhuan.zoro.build` 前端提取的官方求解引擎，脱离站点在本机运行。不联网、不登录、不消耗积分。

## 双击打开

`打开本地求解器.bat` → 浏览器打开 `index.html`。

## 用截图直接解

1. **上传**：点「上传截图」，或把图片拖进棋盘区域，或直接 `Ctrl+V` 粘贴。
2. **自动切块**：默认按 **14 行 × 10 列 = 140 格**切分；行/列可改，改完自动重算。
3. **自动识别**：把 140 格聚类成若干种物品，每种用**它自己的真实裁切图**当图标——所以棋盘看起来就是原图，不会出现「像但不对」的替代图标。
4. **核对**：右侧列出所有物品和数量；每种数量必须是偶数，否则这盘清不空。
5. **改判**：点某个格子（蓝框），再点右侧对应物品即可修正；双击物品可以改名。
6. **求解**：点「求解」，步骤按序列出，点某一步会在棋盘上高亮；「播放」自动走一遍。

识别偏了（比如截图带游戏 UI）就展开「网格校准」，拖四个滑块微调边界，松手自动重新识别。

## 识别是怎么做的

不依赖外部图集，也不需要联网：

1. **定位棋盘**：同时跑三套候选——蓝白皮肤的深蓝竖线 + 白色横缝、格子底色连通域（纯色皮肤）、梯度自相关。三套都只是粗定位。
2. **质心精修**：用每列 / 每行图标的亮度质心做最小二乘拟合，把偏移和格距一起修正。这一步是关键，换皮肤、截图带边框也能对齐。
3. **切格采样**：每格取中间 86% 的区域缩到 28×28，再做 16 个 ±1.5 / ±4.5 像素的平移采样，取最大相关。
4. **聚类**：贪心建类 + 3 轮均值迭代 + 合并相似类；同一物品即使被拆成两半也会合回去。

> 已用两套皮肤的实拍图验证：绿色皮肤 35 类全偶数、蓝色皮肤 36 类全偶数，均 70 步解完。

## 命令行

```bash
# 站内演示盘（4×4）
node solve.mjs

# 直接给矩阵：行x列 + 逗号分隔的颜色编号（0 为空格）
node solve.mjs 4x4 "1,2,2,3,4,3,1,4,3,4,1,2,2,3,4,1"

# 从 JSON 读，适合批量
node solve.mjs board.json
```

`board.json`：

```json
{ "rows": 14, "cols": 10, "cells": [1,2,3,...], "flags": [0,0,...] }
```

输出为 JSON：`solved` / `steps` / `nodes` / `elapsedMs`，每步带一句中文说明。

## 数据格式

| 字段 | 含义 |
| --- | --- |
| `cells` | 长度 `rows*cols`，`0` 是空格，`1..N` 是物品编号 |
| `flags` | 同长度，一般全 `0`；`1` 或 `4` = 锁定块，`2` = 可变块，`8` = 不计入剩余 |
| `steps` | `elim{a,b}` 点击消除两块；`slide{from,dir,dist,to,partner,pushed}` 滑动 |

`dir` 取值 `U/D/L/R`；下标从 0 开始，按行优先（`index = 行 * cols + 列`）。

## 性能（本机实测）

| 棋盘 | 结果 | 用时 |
| --- | --- | --- |
| 4×4 演示盘 | 8 步解出 | 约 60 ms |
| 8×8 随机 | 32 步解出 | 77 ms |
| 10×10 随机 | 50 步解出 | 78 ms |
| 14×10 实拍（绿色皮肤） | 识别 35 类，求解 70 步 | 识别 1.4 s / 求解 31 ms |
| 2×2 构造死局 | `exhausted: true` | 立即 |

## 文件

- `index.html` — 截图识别 + 求解（求解器源码已内联，可离线双击打开）
- `manual.html` — 旧版纯手动涂色页（不想上传截图时用）
- `solve.mjs` — 命令行入口
- `engine/solver.worker.js` — 提取自站点的原始 worker（21,132 字节，未改一行）
- `engine/bridge.mjs` — 把浏览器 Worker 全局适配到 Node
- `逆向报告.md` — 站点计费/接口/风控的完整分析
